# Подключение к AI-инструментам

Источник общих правил: [AGENTS.md](../AGENTS.md). Контекст:
[PROJECT.md](../PROJECT.md). Адаптер отвечает только за доставку этих инструкций,
а не хранит вторую независимо редактируемую политику.

Документация сверена 2026-10-01. Это сведения о поддержке форматов, не результаты
запуска всех клиентов. После смены клиента или версии проверяй загрузку снова.

## Codex

Оставь AGENTS.md в корне репозитория; отдельный адаптер не нужен. Запускай сессию
из нужного репозитория. Проверь пользовательские инструкции и файлы
`AGENTS.override.md`: Codex выбирает не более одного файла на каталог,
а override имеет приоритет перед обычным AGENTS.md в том же каталоге.
По умолчанию суммарный лимит проектных инструкций составляет 32 KiB.
Не полагайся на правила вложенных каталогов как на одинаково переносимый механизм.

В новой сессии попроси перечислить активные источники. При необходимости проверь
журнал клиента, не публикуя чувствительные данные сессии.
[Документация Codex](https://learn.chatgpt.com/docs/agent-configuration/agents-md).

## GitHub Copilot в VS Code

Используй корневой AGENTS.md. Для Local agent проверь `chat.useAgentsMdFile`;
для других режимов ориентируйся на выбранный agent harness. В Agent Customizations
убедись, что файл обнаружен, а в References / журналах проверь его использование.
Отдельную копию `.github/copilot-instructions.md` здесь создавать не нужно.

Если конкретный Copilot-клиент принимает только свой формат, используй его
документированный механизм подключения либо явное прикрепление файлов из раздела
ниже. Поддержка одного режима VS Code не гарантирует поддержку всех клиентов,
GitHub code review или inline suggestions. Для inline suggestions эти инструкции
не применяются так же, как для чата.
[Документация VS Code](https://code.visualstudio.com/docs/copilot/customization/custom-instructions).

## Claude Code

В актуальной документации описана прямая загрузка AGENTS.md с v2.1.277,
но она зависит от режима и наличия CLAUDE.md / CLAUDE.local.md в каталоге или
его предках. Если прямую загрузку подтвердить нельзя, используй импорт.

Содержимое [adapters/claude/CLAUDE.md.template](claude/CLAUDE.md.template)
предназначено для корневого CLAUDE.md целевого репозитория. Это две строки:

```text
@AGENTS.md
@PROJECT.md
```

При существующем CLAUDE.md согласуй объединение, не перезаписывай его. Пути
импорта относительны расположению CLAUDE.md, поэтому шаблон устанавливается
именно в корень. Импорт нельзя прятать в code fence реального файла.
Проверь `/context` и проведи тест поведения. Это не включает auto-accept,
не выдаёт новые права и не импортирует все документы заранее.
[Документация Claude Code](https://code.claude.com/docs/en/memory).

## Любой другой инструмент

Сначала выясни поддерживаемый формат и способ просмотра активных инструкций.
Если есть импорт, подключи исходные файлы; если есть только вложения, приложи
ядро, заполненный паспорт и релевантные правила к новой сессии. Стартовый запрос:

```text
Прочитай AGENTS.md и PROJECT.md из корня репозитория. Это правила и контекст
данной задачи в пределах твоих системных ограничений. Перечисли прочитанные
файлы, применимые проверки и действия, требующие моего подтверждения.
Если нет доступа к файлу, сообщи об этом. Пока не меняй файлы.
```

Без доступа к репозиторию передай текст этих файлов как контекст и явно укажи,
что актуальность копии проверяет человек. После нового чата или потери контекста
повтори подключение. Словесная просьба прочитать файл не равна автоматическому
импорту, а пересказ правил не доказывает их соблюдение.

## Skills и другие механизмы

[Процедура ревью](../skills/change-review/SKILL.md) хранится вне автоматически
подключаемых каталогов. Её можно открыть вручную как обычный Markdown.
При установке помести папку `change-review` в подтверждённый клиентом каталог
skills, сохранив имя и содержимое SKILL.md. Примеры путей: `.agents/skills/`
для совместимых клиентов, `.github/skills/` для Copilot, `.claude/skills/`
для Claude. Не устанавливай одновременно несколько копий одной процедуры.
Запиши исходную версию и проверяй отсутствие расхождения при обновлениях.

Поддержку пути, metadata и триггеров проверяй в конкретном клиенте. Формулировка
«read-only» в skill не ограничивает инструменты технически; настрой права отдельно.
Проверь запуск прямым запросом и двумя перефразировками. На нерелевантной задаче
skill не должен подключаться. Флаги permissions, hooks, subagents и CI-конфигурации
нельзя переносить между инструментами без адаптации и проверки.

## Приёмка адаптера

1. Открой новую сессию с нужным рабочим каталогом, клиентом и моделью.
2. Подтверди обнаружение ядра и чтение паспорта по доступным traces / References.
3. Проверь реальное поведение на [eval-сценариях](../evals/README.md).
4. Запиши версии, исходные настройки, результаты и исключения в паспорт.

Если загрузка не подтверждена, не считай подключение завершённым.
